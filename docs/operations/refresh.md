# 刷新与空订阅

刷新先下载并完整解析候选内容，再用 Mihomo 检查全部候选节点，包括尚未分组的节点。下载、解析、编译和内核检查都在写事务外完成。发生错误只记录脱敏诊断，旧节点、草稿和订阅产物继续有效。

同一来源的原始节点名称精确匹配：大小写、Unicode 组合方式和尾随空格均不归一化。参数变化保留 ID；名称消失时标记失效，并清理所有当前草稿和已发布定义中的成员引用。直接节点规则保留匹配条件、参数和顺序，目标改成 REJECT。空组仍保留并导出 REJECT。恢复的同名节点沿用原 ID，但不会恢复已经移除的成员关系或规则目标。

自动发布从每套方案当前的已发布定义生成。草稿独立执行引用清理，其他人工编辑原样保留。所有受影响的发布结果必须通过检查；节点快照、草稿补丁和发布指针在一笔事务中提交。缺失链式代理等不能安全编译的变更会整次失败，不能靠移除链式设置变为直连。

合法 `proxies: []` 创建待处理项。未选择时不变；“保留旧数据”结束该次提示；“清空节点”执行上述同一套原子清理和发布检查。相同来源版本和候选摘要的重复空结果合并。后续非空成功刷新（即使节点内容相同）或编辑来源配置都会使旧选择过期，旧确认返回 409。

刷新提交先比较用户数据修订号，再核对来源、方案和草稿版本。其他来源更新、人工保存或新增方案会触发重新计算，最多三次；本来源配置或有效快照已变化则拒绝旧下载结果。无内容变化不新建发布版本。历史记录中的计数及规则、空组 ID 用于界面解释自动清理，不记录节点密码或完整上游 URL。
