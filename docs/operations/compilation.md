# 配置编译

编译器只接收方案 ID、定义、节点池和来源版本，不读取数据库、不抓取网络、不启动内核。发布流程在编译完成后单独运行固定 Mihomo 校验。

所有定义的代理组都会输出。节点范围包括组成员、嵌套组、规则直接目标，以及节点的 dialer-proxy 依赖；未使用节点不输出。节点和组组成同一依赖图，混合循环和缺失依赖都会阻止发布。

节点输出名称为 `原始名称 · UUID的22字符base64url编码`，UUID 编码没有 padding。来源显示名称、节点列表顺序和连接参数变化都不改变输出名称。组名保留用户输入；组名与节点输出名或内置策略冲突会报错。无法在规则语法中表示的目标名称会定位报错，可通过一个名称有效的代理组间接引用节点。

空组输出一个 REJECT 成员，所有组均写入 `empty-fallback: REJECT`。第一版只支持手工 select / url-test 组；include-all、use、动态过滤以及不能安全改写的命名默认成员不会被静默接受。

代理组和规则保持文档顺序，节点按 UUID 字符串排序，节点连接参数与组/规则集选项按字段名稳定排序。基础 YAML 保持字段语义和映射顺序。相同输入产生相同 YAML 字节与 SHA-256 摘要。

规则集 path 使用 `./rules/<方案UUID>/<规则集UUID>.<格式>`，与用户可修改的名称分离。产物记录实际使用的来源快照版本；原始连接、请求头等秘密仍只存在于加密存储和显式配置输出中。

空组字段依据固定版本的[官方组解析器](https://github.com/MetaCubeX/mihomo/blob/v1.19.33/adapter/outboundgroup/parser.go)，并使用同版二进制执行集成验证。
