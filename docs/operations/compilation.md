# 配置编译

编译器只接收方案 ID、定义、节点池和来源元信息（名称、配置版本、快照版本），不读取数据库、不抓取网络、不启动内核。来源名称与版本在同一个账户快照中读取，发布时继续校验并发变化。发布流程在编译完成后单独运行固定 Mihomo 校验。

所有定义的代理组都会输出。节点范围包括组成员、嵌套组、规则直接目标，以及节点的 dialer-proxy 依赖；未使用节点不输出。节点和组组成同一依赖图，混合循环和缺失依赖都会阻止发布。

订阅节点输出名称为 `原始名称 · 来源名称`，例如 `中国台湾·2 · 常用订阅`。来源名称可在“上游订阅 → 编辑 → 来源名称”中填写为便于识别的别名，不需要新增节点或重新添加组成员。本地节点使用 `原始名称 · 本地节点`；删除订阅并选择保留本地节点后，来源后缀也改为“本地节点”，节点 ID、连接参数、分组成员和路由关系保持不变。

当完整节点名重名（包括订阅重名、同一订阅下不同协议的同名节点）或与代理组名冲突时，节点名才追加 UUID 的短十六进制标识；默认 8 位，必要时延长，保证唯一。分配顺序按节点 UUID 稳定排序，并为所有普通节点名预留空间，避免短标识占用另一个节点的名称。组名保留用户输入，组之间或与内置策略冲突仍报错。

来源标签两端空白会去除，连续空白和控制字符压缩为空格，英文逗号转换为中文逗号，避免来源名称破坏直接指向节点的规则文本。原始节点名仍按原有语义保留；无法在规则语法中表示的目标名称会定位报错，可通过一个名称有效的代理组间接引用节点。

代理组、规则目标、dialer-proxy 均通过同一份 UUID 到输出名称的映射生成。内部节点身份和分组关系仍使用 UUID，订阅改名不会改变它们。更改来源名称或升级命名规则不会直接重写历史发布记录；在方案重新发布或关联上游成功刷新、重新生成产物后，订阅链接采用新名称，客户端需更新订阅。来源名称、重名集合或冲突组名变化可能改变输出名称，因此客户端之前按名称记住的节点选择可能需要重新选择。

空组输出一个 REJECT 成员，所有组均写入 `empty-fallback: REJECT`。第一版只支持手工 select / url-test 组；include-all、use、动态过滤以及不能安全改写的命名默认成员不会被静默接受。

代理组和规则保持文档顺序，节点按 UUID 字符串排序，节点连接参数与组/规则集选项按字段名稳定排序。基础 YAML 保持字段语义和映射顺序。相同输入产生相同 YAML 字节与 SHA-256 摘要。

规则集 path 使用 `./rules/<方案UUID>/<规则集UUID>.<格式>`，与用户可修改的名称分离。产物记录实际使用的来源快照版本；原始连接、请求头等秘密仍只存在于加密存储和显式配置输出中。

空组字段依据固定版本的[官方组解析器](https://github.com/MetaCubeX/mihomo/blob/v1.19.33/adapter/outboundgroup/parser.go)，并使用同版二进制执行集成验证。
