## 执行裁定（按发生顺序）

1. 使用应用创建的隔离 worktree，并通过已授权的提权命令写入。代价：本地工具审批开销；产品行为不变。
2. 固定并随仓库保存校验过的 geodata，避免构建依赖可变 latest 资源。代价：仓库增大，资源更新需手动验证。
3. 规则导入预览增加节点目录和可选未保存文档，以解析共享节点及新建组。代价：请求体较大；仍为只读且受版本检查。
4. 编译与发布准备显式传入 profileId，用于方案独立的规则集缓存路径。代价：内部接口多一个参数；公开 API 不变。
5. 定时任务复用 `next_refresh_time`，不增加同义的 `next_run_at`。代价：维护时须使用既有列名；行为不变。
6. 本机 pnpm 通过临时 PATH 入口调用固定版本，避开旧全局 Corepack。代价：本机验证需要入口前缀；Docker 与交付命令使用标准 pnpm。
7. 可信出站代理的 DNS、路由由部署者控制；应用无法固定代理端解析。误配置代价：代理可能访问私网目标。
8. 不读取原始私有 `全部节点合并.yaml`，按要求以合成夹具验证兼容性。代价：该文件实际导入时可能仍需迁移不支持的内容。
9. 不连接真实生产 MySQL、不部署实际 HTTPS 代理或操作用户 Clash Verge，仅进行隔离验收。代价：部署环境的 TLS、权限与客户端差异仍需现场验证。
10. 离线校验不保证节点可达、速度、远程规则内容或旧内核兼容性。代价：有效配置在实际网络或其他内核上仍可能失败。
11. 首版维持单应用实例，不扩展集群初始化和调度。代价：多实例运行不受支持，可能产生初始化或调度竞争。
