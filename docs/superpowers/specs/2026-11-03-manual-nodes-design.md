# 手动节点维护增量设计

## 目标与已确认行为

用户希望像桌面代理客户端一样手动添加、编辑、删除单个节点，并在现有代理组中使用。用户已选择：修改后检查相关方案，再手动发布；保存节点不能直接改变已发布订阅。

继续使用 Spring Boot / Java 21、MySQL、Vue 3 + TypeScript，不新增运行时依赖或远程转换服务。维护对象是当前用户的共享本地节点，各套方案可复用。已有完整配置导入及订阅转本地的节点也可维护。

## 方案取舍

采用现有本地节点模型，编辑影响草稿，发布时才生效。这与用户选择及现有导入/关联流程一致。保存后自动更新所有订阅会改变线上行为，用户未选择。把手动节点伪装成远程订阅会混淆刷新语义，不采用。

## 界面与输入

- “上游订阅”提供“订阅来源 / 手动节点”切换，手动节点列表可新增、编辑和删除。
- “统一节点池”增加本地来源筛选以及本地节点的编辑、删除操作；远程节点仍由订阅维护。
- 新增支持两种方式：粘贴单个分享链接或单节点 Clash YAML；按协议表单填写名称、服务器、端口、认证及常用 TLS/传输参数。
- 支持当前矩阵中的九种 YAML 协议；分享链接沿用已有七种 URI 适配器，不扩大协议矩阵。
- 高级连接参数使用可校验的 JSON 编辑，编辑已有节点时保留未在常用表单中展示的字段。切换协议会明确提示重置协议参数；取消不写入。
- 链式代理单独通过目标引用维护，允许现有节点或 DIRECT / REJECT；禁止跨用户引用及循环。粘贴 YAML 中的命名依赖必须唯一匹配，否则提示手动选择，不猜测。
- 一次输入只接受一个节点；不在本次加入批量导入、测速、二维码、分享链接导出或订阅节点覆写。

## 数据与一致性

- 本地节点保留稳定 ID，`source_id` 为空，连接内容继续加密保存。使用已有 `snapshot_version` 作本地编辑版本，更新及删除均校验期望版本。
- 添加/编辑先验证协议字段、归属、引用和实际 Mihomo 配置，成功后在短事务内检查 owner revision 并写入。验证失败不产生部分数据；所有秘密响应 `no-store`，日志不含输入。
- 修改后，所有在草稿中直接或间接使用该节点的方案递增草稿版本，提示受影响方案需要重新发布。旧浏览器草稿不能覆盖新状态。
- 删除先展示受影响草稿和发布方案；确认时校验节点版本及预览时的 owner revision。删除仅清理草稿中的组成员，直接规则目标改为 REJECT，空组沿用 REJECT 回退。若仍被其他节点作为链式代理依赖，拒绝删除并列出依赖节点，先解除依赖。
- 已发布产物与 Token 保持原有语义：必须重新发布才使用新的本地参数或移除节点。
- `StoredRelease` 已保存所使用的完整节点快照。自动刷新重编译已发布定义时，把该发布中的本地节点快照覆盖到候选节点目录，保留当前远程节点更新；提交新发布时保存同一份实际编译目录，防止连续自动刷新泄漏未发布的手动修改。
- 方案状态增加“存在未发布本地节点修改”的判定，避免定义文本没变却显示已与发布一致。新发布后该标记清除。
- 继续保留现有缺失链式依赖时整体拒绝自动刷新的规则。

## 接口和组件边界

接口集中于 `/api/v1/local-nodes`：单节点解析、创建、带版本详情、修改、删除影响与确认删除。列表复用 `/api/v1/nodes?localOnly=true`；详情仅允许操作本地且归属当前用户的节点。

`LocalNodeService` 负责验证和候选计算，`LocalNodeCommitter` 负责事务和草稿更新。`LocalNodeInputParser` 处理单节点文本输入。节点 DAO 只增加本地更新/停用及列表筛选。发布自动更新读取已存本地快照，不复制一套发布流程。

前端组件：`ManualNodesPanel` 管理本地列表；`LocalNodeEditor` 管理输入与校验；`LocalNodeForm` 呈现协议表单和高级参数；共享操作组件管理加载详情、保存、删除预览及请求生命周期，供两个页面复用。页面仅编排。

## 验证与交付

先用失败测试覆盖真实接口缺口，再实现。覆盖创建/修改/删除、加密、跨用户拒绝、远程节点拒绝、版本冲突、协议和内核拒绝、依赖引用、相关草稿状态及两轮远程刷新后本地参数仍被固定；人工发布后使用最新参数。前端测试覆盖两种输入、保留高级字段、删除影响、失败保留输入和异步详情不串节点。

运行全部前后端检查及构建。使用合成节点完成本地界面/API 流程，不访问真实上游，不修改现有真实节点和用户方案。更新运行中的开发服务、文档与源码包。
